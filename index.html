✦The request path

From browser to database

Every request takes the same road. Campus identity is resolved at the edge, checked at the gateway, and enforced again in the database.

1
InternetApplicant, student, parent, faculty, staff or transport manager.
↓
2
CDN + WAF — CloudflareStatic assets at the edge, tenant subdomains resolved, bots and floods filtered.
↓
3
API gateway — NGINXTLS, rate limiting, request ID, JWT pre-check.
↓
4
NestJS modular monolithAuth and tenancy guards, then the module that owns the request. Every mutation is audited.
↓
5
Data and infrastructurePostgreSQL with row-level security, Redis, BullMQ, Meilisearch and S3.

✦Data & infrastructure

What sits underneath

Postgres is the source of truth. Everything else exists to make reading it fast, doing work later, or storing what does not belong in a row.

PostgreSQL 16

Primary plus read replicas. Row-level security scopes every tenant table to one campus.

SQL · RLS

Redis 7

Cache, rotating QR tokens, rate limiting and pub/sub for live updates.

Cache · Pub/Sub

BullMQ

Background queues for PDFs, notifications, imports and reports.

Instant search across students, books and staff, scoped per campus.

✦Summary

The core stack

Five layers, a short list. Anything not here is a dependency we did not need.

Frontend — web

Next.js 15 with React and TypeScript. Public site server-rendered, portals installable as a PWA, admin console client-side.

Next.js 15 · React · TypeScript

Frontend — mobile

One React Native app for students, parents and faculty, with QR scanning and GPS built in.

React Native · Expo

Backend

NestJS modular monolith in TypeScript. REST for everything, WebSocket for what must be live.

NestJS · REST · Socket.IO

Data & storage

PostgreSQL 16 with replicas, Redis 7 for cache and queues, Meilisearch for search, S3 or MinIO for files.

Postgres · Redis · BullMQ · S3

Infrastructure

Docker images on Kubernetes, NGINX as the gateway, Cloudflare for CDN and WAF, GitHub Actions for CI/CD.

Docker · K8s · NGINX · Cloudflare
